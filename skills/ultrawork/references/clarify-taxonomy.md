# Clarify Taxonomy —— 10 类歧义扫描（Stage 1）

在 spec 定稿前，对需求做结构化歧义扫描（借鉴 GitHub Spec-Kit 的 `/clarify`）。目的：把"AI 自以为懂"的模糊点在写代码前逼出来，转成 spec 里可测的边界/IO/验收。

## 用法
1. 逐类扫需求，标出"未定义 / 有多种解读 / 缺量化"的点。
2. 命中的点 → 用 **AskUserQuestion** 一次问清（同类合并，别一条条烦用户）。
3. 用户答复回填进 `spec.md` 对应字段。全部消歧后 spec 才定稿。

## 10 类

| # | 类别 | 扫什么 | 典型澄清问题 |
|---|---|---|---|
| 1 | 功能范围 | 边界在哪、含不含某场景 | "导出功能要不要含定时导出？只当前页还是全量？" |
| 2 | 领域模型 | 实体/关系/状态机是否明确 | "订单有哪些状态？谁能触发哪个流转？" |
| 3 | 交互流程（UX） | 页面/步骤/反馈路径 | "提交失败后停在原页还是跳转？错误怎么展示？" |
| 4 | 非功能属性 | 性能/安全/可用性有无量化 | "‘快’是多少 P95？并发峰值多少？" |
| 5 | 集成 | 外部系统/接口/依赖 | "对接哪个支付网关？回调协议？超时重试策略？" |
| 6 | 边界与异常 | 空/超限/并发/越权/幂等 | "重复提交怎么处理？余额不足返回什么？" |
| 7 | 约束 | 技术/合规/兼容/时间 | "必须兼容旧数据吗？有无框架版本锁定？" |
| 8 | 术语 | 同词不同义 | "‘用户’指登录账号还是自然人？‘活跃’口径？" |
| 9 | 完成信号 | 怎么算做完（验收） | "这个功能的验收断言是什么？谁签收？" |
| 10 | 占位符 | 需求里的 TODO/待定/示例值 | "这里写的 ‘xxx’ 是真值还是占位？" |

## 红线
- 命中"金额/统计/报表 / DDL / 契约"相关的模糊点 → 除了澄清，还要在 spec 标注 **human-gate 卡点**，交付阶段强制停。
- 澄清不了、用户暂不定的 → 记为 spec 的"未决项 + 假设"，不要自行拍板当成事实实现（那是"替换成更容易的问题"）。
