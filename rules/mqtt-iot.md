# MQTT IoT 通信规则

## 主题设计
- 使用层级结构: `{项目}/{功能}/{设备SN}`
- 上行(设备→云): 主动上报用固定主题，响应用 `回复主题/{sn}`
- 下行(云→设备): 指令下发用 `指令主题/{sn}`，一对一精确投递
- 避免使用通配符订阅大量设备主题，优先用共享主题分摊负载

## QoS 选择
- 遥测数据(高频、可丢): QoS 0
- 指令下发(必达): QoS 1
- 不使用 QoS 2，IoT 场景下性能代价过高

## 连接管理
- 使用 cleanSession=false 保留离线消息
- 配置 LWT (Last Will and Testament) 检测设备异常断连
- clientId 必须唯一，推荐用设备SN，防止互踢
- 实现指数退避重连，避免 broker 雪崩

## 消息处理
- 消息回调中不做重计算，快速消费后交给异步线程处理
- 解析前先校验消息最小长度，防止越界
- 同一设备的消息保证顺序处理，不同设备可并行
- 注意帧声明长度与实际载荷长度不一致的情况

## 安全
- 生产环境启用 TLS 加密
- 使用用户名/密码或证书认证
- 限制每个客户端的发布/订阅权限（ACL）
- 不在 MQTT 主题或 payload 中传输明文密钥
