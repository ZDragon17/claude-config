# Global Coding Standards

## 语言规范
- **必须全量使用中文回复**，包括：
  - 所有解释、说明、总结
  - 错误信息和提示
  - 代码注释（新增或修改时）
  - 文档内容
- 仅以下情况保留英文：
  - 代码本身（变量名、函数名、关键字）
  - 技术术语首次出现时可附英文原文，如：虚拟线程（Virtual Thread）
  - 命令行输出和日志原文
  - 引用的外部文档原文

## 代码质量
- 代码应当自文档化，变量和函数名要有意义
- 函数保持单一职责，不超过 50 行
- 避免深层嵌套（最多 3 层）
- 使用早期返回减少嵌套

## 错误处理
- 永远不要吞掉异常
- 提供有意义的错误信息
- 记录错误上下文以便调试

## 注释原则
- 解释"为什么"，而不是"做什么"
- 删除注释掉的代码
- TODO 注释要包含责任人和日期

## 安全意识
- 永远不要硬编码敏感信息
- 验证所有外部输入
- 使用参数化查询

## 性能意识
- 避免在循环中进行数据库查询
- 优先使用批量操作
- 考虑缓存频繁访问的数据

## Bug 修复验证规则（基于 Insights 优化）

修复 Bug 后，**必须**：
1. 编写或更新相关测试用例验证修复
2. 运行测试确认通过
3. 如无法编写测试，说明原因并提供手动验证步骤

**目的**: 避免 "修复→部署→再次失败" 的循环
